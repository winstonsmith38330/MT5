# Windows activation

Run on Nicolas's Windows host, not in cloud. No account password/token should be pasted into ChatGPT, source control or command history. Use the terminal's local login UI and Windows Credential Manager or session-only environment bindings. A current official broker/MetaQuotes installation is required; acquire binaries normally, never from this repository.

## Install the Python tools

Install supported Python 3.12 (64 bit) from the official Python distribution. In PowerShell:

```powershell
git clone https://github.com/winstonsmith38330/MT5.git
Set-Location MT5
./scripts/windows/Setup.ps1
New-Item -ItemType Directory -Force local, local/sources, local/presets, local/outputs | Out-Null
Copy-Item examples/worker.example.json local/worker.json
Copy-Item examples/native-policy.example.json local/native-policy.json
$env:MT5_RESEARCH_ROOT = (Resolve-Path local).Path
```

Do not overwrite an existing clone or existing local configuration; pull/review normally if it already exists. `Setup.ps1` never installs/changes MT5 itself. Its offline tests must pass before connecting a broker. Paths in `worker.json` are workspace-relative.

## Dedicated MT5 installation and path discovery

Install a **separate** terminal into `<repo>/local/terminal` (a writable folder outside Program Files). Start that copy with `/portable`. Its data directory must equal its installation directory. Do not point the worker at the interactive terminal. Open File → Open Data Folder in that dedicated terminal and confirm the path. Confirm `terminal64.exe`, `metaeditor64.exe` and the standard `MQL5/Include` files exist there. Edit `local/worker.json` if names differ. This explicit declaration is required; a folder name alone is not proof of isolation.

```powershell
./scripts/windows/Discover-Paths.ps1
Start-Process "$env:MT5_RESEARCH_ROOT/terminal/terminal64.exe" -ArgumentList '/portable'
```

Path discovery prints candidate executable/data locations only; it neither picks nor kills a terminal. In the dedicated terminal, log into a **demo** account through the UI, permit history download and verify the broker/server. Disable automated account trading, DLL imports and dangerous AI shell operations. Use an empty chart profile without attached EAs/scripts. Store credentials through MT5's normal local UI; no `[Common] Login/Password` section is generated by these tools.

Close that dedicated terminal before fallback `broker_inspect`, export or tester jobs. Those jobs explicitly start their own portable process, initialize its stored demo connection, and close only their own process. A pre-existing dedicated process causes a refusal, protecting sessions from ignored `/config` options. Another installation may remain open. Compilation similarly requires the dedicated MetaEditor to be closed. For native discovery, open the dedicated terminal and MetaEditor; close them again when switching to fallback jobs.

## Native MCP first

In the dedicated terminal, Tools → Options → MCP: enable its internal server, keep the listener on loopback, generate an API key and use Copy to obtain its actual endpoint. Do the equivalent for MetaEditor. The official documentation examples use 22345/22346, **but these are not discovered values**. Keep trading and dangerous shell capabilities disabled in application settings. Copy only the URL into local configuration; transfer the generated token securely into the session environment.

For session-only entry without a literal token in command history:

```powershell
$secure = Read-Host 'Dedicated terminal MCP token' -AsSecureString
$env:MT5_TERMINAL_TOKEN = [System.Net.NetworkCredential]::new('', $secure).Password
$secure = Read-Host 'Dedicated MetaEditor MCP token' -AsSecureString
$env:MT5_EDITOR_TOKEN = [System.Net.NetworkCredential]::new('', $secure).Password
$env:MT5_TERMINAL_URL = Read-Host 'Copied terminal loopback MCP URL'
$env:MT5_EDITOR_URL = Read-Host 'Copied MetaEditor loopback MCP URL'
./.venv/Scripts/mt5-research.exe --workspace local discover terminal > local/terminal-tools.json
./.venv/Scripts/mt5-research.exe --workspace local discover editor > local/editor-tools.json
```

Review actual `inputSchema`, descriptions, permissions and workspace paths in those outputs. They contain `schemas`, enabled names and missing categories. The official website's tool list does not establish installed capability. No MT5 schema was discoverable in the cloud task.

For direct local Codex, copy `examples/codex-native.toml` into that project's `.codex/config.toml` **after replacing the URL placeholders**. Merge with existing settings. The current Codex bearer environment setting keeps tokens out of TOML. `enabled_tools=[]` intentionally enables no operations; fill only exact reviewed names from discovery. If the Codex version lacks that configuration option, update it or use the gateway, not a real committed header. Never enable `trade_*`, `shell`, arbitrary `send_web_request`, chart EA/script attachment or unrestricted file tools. Direct native mode relies on Codex's reviewed tool selection and terminal settings; the repository gateway's additional file validation applies only when using the gateway.

The gateway's `native-policy.json` starts empty. For a read-only tool, copy its exact discovered name, review its schema, and set `reviewed`, matching `category` and exact `fixed_arguments` locally. Example, **only if installed schema accepts an empty object**:

```json
{"terminal":{"get_workspace_info":{"reviewed":true,"category":"inspect","fixed_arguments":{}}},"editor":{}}
```

Source reads and `compile_file` additionally require `path_fields`, mapping the actual schema's argument name to `source`; all mapped paths must be beneath workspace `sources`, and files must be `.mq5`/`.mqh`. Use actual absolute Windows paths in fixed arguments when the native tool expects them. This deliberately prevents arbitrary source traversal. No parameter name is assumed by the repository. `tester_get_status`/configuration/report/journal reads can be reviewed similarly with fixed run identifiers. Hosted native tester start/configuration mutation and native data export are **disabled pending schema-specific bounded adapters**; use the implemented dedicated CLI tester/export jobs instead. Missing categories are reported honestly. If direct local native tools suffice, no forwarding middleware is needed for that mode.

## Start the bounded gateway and run the pipeline

```powershell
./scripts/windows/Start-Gateway.ps1 -Workspace local
```

Keep it open. It binds only `127.0.0.1:8765/mcp`. Use `examples/codex-gateway.toml` for local Codex, or the tunnel instructions for hosted ChatGPT. Call `health_check`; demand actual Windows paths, build, broker/server and DEMO scope. Health may initialize an existing dedicated session; close it before fallback jobs. MOCK or missing connection is not readiness.

In another PowerShell window, with the dedicated terminal closed:

```powershell
./.venv/Scripts/mt5-research.exe --workspace local call --request examples/inspect-request.json --wait
```

Pick the exact returned EURUSD and NAS100 broker aliases, verifying descriptions/contract specifications. Do not assume a broker offers the literal string `NAS100`. Supply the EA and all local includes under `local/sources/<project>/`; supply its `.set` under `local/presets/`. No example strategy is created. Copy and edit the request templates under `local/`:

```powershell
Copy-Item examples/compile-request.json local/compile-request.json
# Edit source path to the supplied .mq5.
./.venv/Scripts/mt5-research.exe --workspace local call --request local/compile-request.json --wait
Copy-Item examples/smoke-request.json local/smoke-request.json
# Edit fresh EX5 path, supplied preset, both discovered aliases, and risk_input
# only if the EA documents a percent input and the preset contains that input.
./.venv/Scripts/mt5-research.exe --workspace local call --request local/smoke-request.json --wait
```

These client commands are defined by this repository; their underlying MCP schemas can be inspected using a normal client. Job IDs/status/cancel are also exposed as tools. The worker logs compiler diagnostics, checks a new EX5, then runs the assets in order. Generated tester INIs are deterministic aside from unique identifiers, optimization/forward/remote/cloud agents are off, and account trading/DLL imports are disabled. Check the **actual report** to confirm tester settings; some broker symbols/accounts constrain leverage/currency/history. Risk is unverified if its mapping is missing; the EA's own sizing semantics remain authoritative.

Find reports, agent journals, available EA output files, manifest and chart/data directories under one `local/outputs/<run-id>/`. Global Common Files are deliberately not swept for privacy/isolation. If the EA uses `FILE_COMMON`, copy its run-identified audit/summary through an explicit local adapter; absent files stay DATA_MISSING. After the EA audit schema is known, supply markers to `chart_job` using `examples/marker-schema.json` as an adapter template. Automatically generated smoke charts show broker-bar references and explicitly warn that audit markers are missing.

Do not upload stored account configuration, credential stores or unreviewed journals. Validate successful trades/settings/audit consistency separately from performance research. Zero trades is INCONCLUSIVE. No Windows compiler, broker export or real tester result has been executed by the cloud handover.
